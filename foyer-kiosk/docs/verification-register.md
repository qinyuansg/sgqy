# Verification register — what is proven, how, and what is still open

"Ready to manufacture" for a new electronic product means **ready to build
EVT units** (engineering validation). Nothing in this package has been built or
powered yet. This register lists every claim, how it was verified in the design
environment, and the gates that must close before PVT/mass production.

## A. Verified in the design environment

| ID | Item | Method | Result |
|---|---|---|---|
| A-1 | CM5 2×100-pin pinout | Raspberry Pi CM5 datasheet (RP-008180-DS) + diff of two independent CM5 carrier designs | 0 differences |
| A-2 | CM5 land pattern | Taken from Raspberry Pi CM5 IO board design data (DF40C-100DS-0.4V(51), 0.4 mm pitch, 33 × 48 mm holes) | Matches reference |
| A-3 | Camera I2C routing (MIPI0 → SDA0/SCL0, MIPI1 → ID_SD/ID_SC) | CM5 datasheet §2.6 + CM5 IO board-derived reference PCB nets | Confirmed |
| A-4 | IC pinouts | Taken programmatically from KiCad's reviewed symbol libraries (KiCad 7 + vendored KiCad 9 symbols); every symbol pin cross-checked against a footprint pad by the ERC | 0 mismatches |
| A-5 | Electrical rules (carrier, 278 parts / 235 nets; sensor bar) | Custom ERC: every pin connected or explicitly NC, no single-node nets, no duplicate refs | 0 issues |
| A-6 | Schematic ⇔ circuit model | KiCad `kicad-cli` netlist export of the generated schematic diffed against the model | 0 differences (both boards) |

## C. Current DRC status

Regenerated by `hardware/*/build.py fab`; summaries in
`hardware/carrier/fab/carrier-drc-summary.json` and
`hardware/sensorbar/fab/sensorbar-drc-summary.json`. Warnings are silkscreen
cosmetics (reference text over pads/edges), which the fab clips automatically.
Any remaining **errors** listed there must be closed by a layout engineer in
KiCad before ordering (see §D-1).
